# 보울게임즈 녹음 자동화 실전 검증

2026-09-21 보울게임즈 녹음 2건으로 접수부터 고객 화면 반영까지 검증했다.

## 완료

- 고객사 연결: `수집대기/보울게임즈` → `bowlgames`
- 원본 파일명은 바꾸지 않고 앞의 `YYMMDD_`를 실제 통화일로 사용
- 녹음 2건 전사 및 회의록 생성 성공
- Notion 커뮤니케이션보드에 2026-09-03·2026-09-11 기록 생성
- 두 기록의 `고객 공개`를 켜고 비공개 고객페이지 DB에 반영
- 원격 최신 보울게임즈 화면 데이터에서 두 날짜의 회의록 2건 확인
- 로컬 처리 장부의 두 작업을 `complete`로 종료

회의록 기본 모델은 Gemini API가 권장하고 실제 성공한 `gemini-3.6-flash`로
조정했다. 일시적인 API 실패는 다음 실행에서 회의록 생성부터 이어서 재시도한다.
형식 검사에서 멈춘 항목은 자동 재시도하지 않고 PM 확인 대상으로 유지한다.

## 공개 운영 결정

2026-09-21 사용자 결정에 따라 새 회의록은 Notion에 `고객 공개=true`로 만든다.
시스템은 고객페이지 반영을 요청하고, 각 PM은 Notion에서 내용을 수정한다.
숨겨야 하는 기록은 PM이 `고객 공개`를 해제한다.

자동화의 고객페이지 갱신 요청은 비공개 Worker의 `/ops/rebuild`를 사용한다.
브라우저에는 자동화 토큰을 전달하지 않는다. 이번 두 기록은 수동 즉시 빌드로
반영했으며, Worker 자동 호출 활성화에는 비공개 Worker의 `AUTOMATION_TOKEN`
등록이 한 번 남아 있다.

## Drive 동기화

이 PC의 Drive Desktop 일시중지 표식을 제거하고 프로세스 실행을 확인했다.
다만 Drive 웹의 「클라이언트 통화 미팅기록」 아래에 같은 이름의 `수집대기`
폴더가 두 개 있어, 자동화가 보는 로컬 폴더와 업로드 폴더가 같은지는 미확인이다.
두 폴더를 확인하기 전에는 삭제하거나 이동하지 않는다.

이번 검증은 사용자가 선택해 업로드한 동일한 로컬 원본 사본을 임시 접수함에서
처리했다. 파일 해시를 처리 장부에 기록했으므로 같은 파일을 다시 처리하지 않는다.

3. 위 두 항목 완료 후 새 녹음 1건으로 무인 반영을 확인한다.
