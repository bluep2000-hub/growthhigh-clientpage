# 클라이언트 페이지 실사용 운영

기준일: 2026-09-18. 코드 인수 기준은 `ae20a98`이다.
사용자가 데이터룸 B안을 우선 선택했으며 추후 의견에 따라 변경할 수 있다.

## 담당자가 사용할 화면

- 고객: `https://client.growthhigh.co.kr/{슬러그}/`
- 담당자: `https://client.growthhigh.co.kr/{슬러그}/?edit`
- 위프코리아 데이터룸: `https://client.growthhigh.co.kr/whiffkorea/?edit#room`
- A안 비교: 담당자 주소에 `&review-room=A`를 붙인다.

고객 비밀번호로 페이지를 연다. 공지사항에서 「담당자 편집」을 켜고 별도의
담당자 비밀번호로 인증하면 데이터룸 자료의 📌 버튼을 사용할 수 있다.
고객은 자료와 즐겨찾기만 읽으며 공지·고정·주요 소통을 수정할 수 없다.

## 자료를 등록하고 공유하기

1. 노션 공유페이지 DB에서 해당 기업의 클라이언트페이지 항목을 연다.
2. `드라이브 URL`, `사업계획서 URL` 또는 `추가 링크`를 채운다.
3. [GitHub Actions의 공지 반영](https://github.com/bluep2000-hub/growthhigh-clientpage/actions/workflows/rebuild.yml)에서
   `Run workflow`를 누르고 해당 기업의 슬러그를 입력한다.
4. 실행 성공 후 고객 주소의 데이터룸에서 자료를 확인한다.

`추가 링크` 예시:

```text
연구노트
2026년 3분기 연구노트 | https://www.notion.so/자료주소
R&D 기획
과제 기획서 | https://www.notion.so/다른자료주소
```

화면 분류는 그룹명과 자료명에 들어 있는 낱말로 결정된다.
자료가 없는 실제 기업에는 예시 자료를 만들지 않는다. 가이드북은 별도 메뉴다.
자료 링크의 Notion·Drive 열람 권한은 담당자가 해당 서비스에서 관리한다.
클라이언트 페이지 비밀번호가 외부 자료의 열람 권한을 대신하지 않는다.

노션 자료 속성을 고치는 것만으로는 재빌드가 시작되지 않는다.
위의 Actions 실행은 비밀값을 입력하거나 터미널을 사용할 필요가 없다.

## 즐겨찾기에 고정하기

1. 담당자 편집 인증 후 데이터룸에서 자료의 📌를 누른다.
2. 사이드바의 즐겨찾기에 올라왔는지 확인한다.
3. 자동 재빌드와 Pages 배포가 성공하면 새 고객 탭에서 결과를 확인한다.

고정은 노션 `고정 자료`에 저장되고 Worker가 기업별 재빌드를 요청한다.
다시 누르면 해제한다. 저장 실패는 즉시 표시하고 화면의 변경을 되돌린다.
재빌드 요청 실패는 고정 저장 성공과 구분해 알린다. 이때 위 Actions에서 재빌드한다.
담당자 탭의 새로고침은 저장 성공한 고정 상태를 유지한다.
기존 고객 탭은 복호화 데이터를 보관하므로 새 탭에서 새 게시본을 확인한다.

## 공지와 주요 소통

- 공지는 페이지에서 작성한다. 자동저장은 D1 초안만 바꾼다.
- 「게시」를 눌러야 고객 게시본과 자동 재빌드가 바뀐다.
- 소통 내역의 ☆/★는 담당자가 선택한다. 노션 `주요사항 확인`이 원본이다.
- 공개 여부는 커뮤니케이션보드의 `고객 공개`로 담당자가 승인한다.

## 인증과 녹음 자동화의 남은 조건

기존 이 PC 작업 폴더에서 `.env`와 `worker/.dev.vars`를 복사했다.
두 파일의 Git 제외를 확인했고 값은 출력하거나 커밋하지 않았다.
복사본의 Notion 토큰은 읽기 200이지만 `BUILD_TOKEN`과 `EDITOR_PASSWORD`는
현재 운영 Worker에서 401이다. `AUTOMATION_TOKEN`은 없다.
운영 서비스의 정상 secret을 오래된 로컬 값으로 덮어쓰지 않는다.

현재 연결된 Drive의 기록 루트는 읽히지만 `수집대기/위프코리아` 접수함은 없다.
이 PC에는 녹음 자동화 예약과 처리 장부가 없다. 다른 업무의 기존 예약은 유지했다.
녹음 자동화는 현재 이 PC에서 실행·등록하지 않았다.

1. 현재 서버와 일치하는 로컬 비밀값을 확보하고 읽기·편집·자동화 인증을 확인한다.
2. 실제 공유 Drive의 고객사별 접수함과 기존 처리 장부를 확인한다.
3. 다른 PC의 녹음 예약이 꺼져 있는지 확인하고 전체 `--dry-run`을 통과시킨다.
4. 담당자가 선택한 시험 녹음으로 전사 → 비공개 초안 → 공개 승인 → 재빌드를 확인한다.
5. `src/install_recording_scheduler.ps1`로 이 PC의 예약을 등록하고 실행 결과를 확인한다.

설치 스크립트는 이 저장소의 `.venv`를 우선 사용하며 `-PythonPath`로 명시할 수도 있다.
예약 시각은 09:00·13:00·18:00이다. 사용자 로그인과 Drive Desktop 연결이 필요하다.
PM이 접수한 고객 통화만 처리하며 휴대전화의 전체 녹음 폴더는 동기화하지 않는다.
원음·전사·회의록은 기존 승인된 임시 영구 보관 정책을 유지한다.

전체 실사용 완료는 📌 실제 저장·고객 반영과 이 PC의 녹음 한 건 처리·예약 검증을
마친 뒤 판단한다. 과거 다른 PC의 시험 성공은 이 PC의 실행 결과가 아니다.
