2026-10-01. 영문 주소 `welldoneproduct`.

## 확인·완료

- 기업 DB 원본 1건 확인. 공유페이지에 같은 고객의 클라이언트페이지는 없었다.
- [Notion 클라이언트페이지](https://app.notion.com/p/3ec815d712b981ad8801c26c6ed60df3) 생성. 기업 관계·담당자 1명, 게시된 1·2차 자료 2건을 연결했다.
- 고객사 필터가 있는 프로젝트 보기와 고객 공개 소통 보기를 생성했다. 원본 프로젝트 0건, 고객 공개 소통 7건이다.
- 최초 메일 단계에서 공용 메일함 1,414통을 300통씩 나눠 확인했다. 제목이 정확히 일치하는 7건을 기존 메일 DB와 커뮤니케이션보드에 기록했고, 재실행에서 추가 0건·중복 건너뜀 7건을 확인했다.
- 비공개 빌드 내용을 메모리에서 수집했다. 프로젝트 0건, 소통 7건, 일정 1건, 게시 자료 2건, 추천 0건, 공지 없음. 실제 고객 데이터는 파일이나 Git에 쓰지 않았다.
- 고객 주소의 담당자 편집 진입점은 HTTP 200이며 비밀번호 설정 화면이 나온다. 게시 자료 2건의 외부 주소도 비로그인 HTTP 200을 확인했다.
- 담당자가 고객 비밀번호를 저장했다. 비공개 D1에서 해당 주소의 등록 건수 1건을 확인했다. 비밀번호 원문은 보지 않거나 기록하지 않았다.
- `--step build`를 실행해 비공개 D1에 고객 데이터를 저장했다. 저장본은 `ready=1`, 프로젝트 0건·소통 7건·일정 1건·추천 0건이다.
- 비로그인 고객 주소는 비밀번호 화면을 표시한다. 미인증 `/welldoneproduct/page/`는 고객 주소로 이동한다.
- 담당자가 고객 비밀번호로 로그인한 화면에서 자료 2건·소통 7건·일정 1건 표시를 확인했다고 회신했다.
- 제공된 웰던프로덕트 로고 PNG를 Notion 클라이언트페이지 아이콘으로 업로드하고 비공개 고객페이지를 다시 빌드했다. 이후 작은 화면에서 글자가 잘 보이지 않아 W 심볼만 남긴 투명 이미지 [`logo/welldoneproduct-symbol.png`](../logo/welldoneproduct-symbol.png)로 아이콘을 교체했다. 최신 D1의 `logo/welldoneproduct.png`는 새 심볼 원본 242,220바이트와 해시까지 일치한다. 로그인 후 화면 표시 자체는 아직 확인하지 않았다.
- 보울게임즈와 동일한 초기 제작 뼈대를 위해 Notion에 빈 컨설팅 타임테이블 표를 만들었다. 비공개 D1에 타임테이블 객체(계획 0건)와 데이터룸 게시 자료 2건이 저장됐음을 확인했다. 고객 화면의 빈 타임테이블 메뉴는 새 화면 코드 배포 후 검수해야 한다.
- 기존 고객 폴더 3곳이 있는 유일한 Drive 접수함 `수집대기 (1)` 아래 `웰던프로덕트` 폴더를 생성했다. 녹음 주소 매핑은 `welldoneproduct`로 등록했다. 폴더에는 Drive가 만든 `desktop.ini`만 있고 녹음은 없다.
- 2026-10-01, 새 화면 코드를 운영 private Worker에 배포했다(버전 `c91f729f-dfe5-4fbc-8008-a0677782d829`). GitHub `main`에도 제작 변경을 반영했다. 비로그인 고객 주소 HTTP 200, 미인증 상세 주소의 고객 주소 이동 HTTP 302를 다시 확인했다.

## 후속 운영

첫 공지와 로드맵은 원본 또는 담당자 판단이 생긴 뒤 반영한다. 비밀번호 원문은 Notion·Git·채팅에 기록하지 않는다.

현재는 **노션 뼈대·메일 연결·비밀번호 등록·비공개 저장·운영 코드 배포·녹음 접수 폴더 생성 완료**다. 로그인 후 새 타임테이블 메뉴와 공통 데이터룸 편집 화면은 아직 육안 확인하지 않았다. 이 PC의 작업 스케줄러에는 녹음 자동화 작업이 보이지 않아 신규 녹음 자동 처리는 미검증이다. 고객에게 주소나 비밀번호를 전달하지 않았다.
