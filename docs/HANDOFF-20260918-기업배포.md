# 다른 PC 인수인계 — 위프코리아 기업 배포

기준일: 2026-09-18. 인수인계 직전 구현 커밋은 운영 `25e5217`, 기획 `af60a1c`이다.
이 문서를 추가한 이후에는 두 저장소의 최신 main을 사용한다.

## 현재 목표와 작업 경계

위프코리아 고객페이지를 기업에 배포할 수 있도록 비공개 고객 DB·서버 인증·갱신 흐름까지 완성한다.
개발은 사용자 승인된 작업이다. 기획만 하던 이전 재개 문구를 현재 작업 지침으로 쓰지 않는다.
다른 기업·샘플 페이지·내부 Hub는 변경하지 않는다. 기존 UI와 완료된 실전 검증은 재사용한다.
문제 정의는 실제 사용 이후에 다시 한다. 새로운 불편이나 KPI 현재값을 만들어 내지 않는다.
작업 묶음이 끝나면 코드·문서를 커밋하고 GitHub에 올려 원격 일치를 확인한다.

## 원격 자원과 현재 설정

- 고객 전용 Worker: `growthhigh-clientpage-private`, 설정 `worker/wrangler.private.toml`.
- 고객 전용 D1: `growthhigh-clientpage-private`, ID `a8fbbb00-fb49-4eb0-85c2-96d5b03a3bd4`, binding `PRIVATE_DB`.
- 기존 중계 서버 `growthhigh-clientpage-relay`와 기존 공지 D1은 그대로 유지한다.
- 신규 서버 마지막 확인 배포: `65facf69-47bf-46d5-a5ff-ff7ab5a31c40`. 공개 route 없음, workers.dev·preview 비활성.
- 신규 서버 secret `AUTH_PEPPER`·`NOTION_TOKEN` 등록 완료. 실제 값은 GitHub에 없다.
- Notion 내부 권한 DB: `3df815d7-12b9-8174-812e-f72174dacc99`.
- 사용자 지정 비공개 하위 페이지: [클라이언트페이지 권한 관리](https://app.notion.com/p/yuncommon/3df815d712b9809d9bbff527632f48d9).
  계정 이메일·API 키 보관 페이지 내용은 공개 문서에 복사하지 않는다.
- 로컬 설정 기준 `GOOGLE_CLIENT_ID`·`APP_ORIGIN`은 미설정이다. 실제 Google 앱 생성·설정 완료도 미확인이다.
- PC 전환 요청 시 제공된 브라우저 URL은 `https://console.cloud.google.com/auth/clients?project=growthhigh-client`였다.
  URL만으로 앱 생성·로그인 성공·설정 저장을 확인한 것으로 판단하지 않는다.
- 마지막 원격 검증: 비밀번호 확인값 1건, 고객 스냅샷 0건, 고객·내부 세션 각각 0건.
  원격 자원은 새 PC에 복사하거나 다시 생성할 필요가 없다.

## 새 PC 준비

두 저장소를 같은 상위 폴더 아래에 받는다. 이미 있다면 미커밋 작업을 먼저 확인한 뒤 최신 main을 받는다.

```powershell
git clone https://github.com/bluep2000-hub/growthhigh-clientpage.git
git clone https://github.com/bluep2000-hub/growthhigh-clientpage-hub.git
```

Codex에서 두 저장소의 상위 폴더 또는 운영 저장소를 연다.
Node.js 24와 Python 환경을 준비하고, 필요한 경우 운영 저장소 `worker`에서 `npm ci`,
Python 가상환경에서 `pip install -r src/requirements.txt`를 실행한다.
GitHub·Cloudflare CLI와 Google 브라우저 로그인은 새 PC에서 각자 인증한다.
브라우저 기록·프로필·세션 쿠키를 인수인계 파일로 올리지 않는다.

### GitHub에서 내려오지 않는 파일

기존 PC의 아래 두 파일은 신뢰할 수 있는 비공개 방식으로 같은 상대 위치에 옮긴다.

- 운영 저장소 루트 `.env`
- 운영 저장소 `worker/.dev.vars`

**두 파일에 추가된 기존 `AUTH_PEPPER`도 같은 값으로 이전한다. 새 값을 생성하지 않는다.**
이미 저장된 비밀번호 확인값과 연결된 secret이므로 임의 변경하면 기존 비밀번호 검증이 실패한다.
값을 화면·로그·문서·GitHub에 출력하지 않는다. 환경 파일이 없으면 빌드·서버 인증 검증을 진행할 수 없다.
`node_modules`, `.venv`, `.wrangler`, 캐시·검증 임시파일은 새 PC에서 필요한 것만 다시 만든다.
녹음 처리 장부는 위 환경 파일과 별개다. 빈 장부를 만들어 이전 완료로 취급하지 않는다.

## 다음 작업 하나

**Google 앱 설정의 실제 상태를 확인하고, 실제 내부 로그인·갱신 UI를 연결한다.**
기존 권한 표와 대표 등록을 재사용한다. 앱이 이미 만들어졌다면 다시 만들지 않는다.
실제 앱 ID·허용 출처·고객 서버 출처를 확인한 뒤 필요한 설정만 보강한다.
고객/내부 쿠키 분리, 서버에서 역할 확인, Google 증명 만료 시 갱신·재인증을 실제 화면에서 검수한다.
Google 증명 만료에 따른 재인증은 현재 API 동작이며, 자동 갱신 UI는 아직 없다.
설정 부재를 공용 담당자 비밀번호로 우회하지 않는다.

그다음 고객용 데이터 투영·기존 빌더/갱신 연결 → 안정화·운영 안내 → 주소 전환 순서로 진행한다.
검수 전 기존 주소·암호화 산출물·Notion 비밀번호를 삭제하지 않는다.
현재 파일 삭제는 GitHub 과거 이력 삭제가 아니다. 이력 정리는 별도 판단이며 자동 강제 push하지 않는다.
녹음 주기는 09·13·18시로 결정됐지만 기존 실행 중지와 장부 확인 전에는 예약을 만들거나 활성화하지 않는다.
