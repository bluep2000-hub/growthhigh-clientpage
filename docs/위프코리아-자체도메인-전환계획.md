# 위프코리아 자체 도메인 전환 계획

기준일: 2026-09-19

## 결론

`client.growthhigh.co.kr/whiffkorea/` 주소를 유지하면서 위프코리아만 비공개
Cloudflare Worker로 보낸다. 제로백과 나머지 공개 페이지는 현재 GitHub Pages를
계속 사용한다. 도메인 전체를 한 번에 새 서버로 옮기지 않는다.

## 변경 전 백업

| 구분 | 현재 값 |
|---|---|
| 네임서버 | `cns1.hostcocoa.com` ~ `cns4.hostcocoa.com` |
| 루트 도메인 | `growthhigh.co.kr` → `3.170.221.23`, `3.170.221.35`, `3.170.221.52`, `3.170.221.112` |
| 고객페이지 | `client.growthhigh.co.kr` → `bluep2000-hub.github.io` CNAME |
| 메일 | `mx1.daouoffice.com` 우선순위 5, `mx2.daouoffice.com` 우선순위 10 |
| 메일 인증 | `v=spf1 include:_spf.daouoffice.com include:mail.stibee.com ~all` |
| Google 확인 | 기존 `google-site-verification` TXT 유지 |
| GitHub Pages | 저장소 루트 `CNAME`이 `client.growthhigh.co.kr` 사용 |
| Cloudflare | 계정에 등록된 도메인 없음. Worker 두 개만 운영 중 |

위 표는 공개 DNS에서 확인한 주요 항목이다. 네임서버 변경 전에 Cloudflare가
자동으로 찾은 전체 레코드와 기존 DNS 관리 화면의 전체 레코드를 다시 대조한다.
하나라도 빠지면 네임서버를 변경하지 않는다.

## 안전한 전환 순서

1. Cloudflare에 `growthhigh.co.kr`을 추가하되 네임서버는 아직 바꾸지 않는다.
2. Cloudflare가 가져온 DNS 레코드를 기존 값과 대조한다.
3. 홈페이지, `www`, 메일 MX·TXT, Google 확인, 고객페이지 CNAME을 모두 보존한다.
4. `client.growthhigh.co.kr`만 Cloudflare를 통하도록 설정한다.
5. Worker는 `client.growthhigh.co.kr/whiffkorea*` 요청만 처리한다.
6. `/zeroback/`과 그 밖의 주소는 기존 GitHub Pages로 그대로 전달한다.
7. Google 로그인 허용 주소와 Worker의 운영 주소를 `https://client.growthhigh.co.kr`로 맞춘다.
8. 변경 직전 기존 DNS 화면을 캡처하고 복구 값을 다시 확인한다.
9. 네임서버를 전환한 뒤 홈페이지·메일·위프코리아·제로백을 차례로 확인한다.
10. 문제가 있으면 Worker 경로를 해제하거나 기존 네임서버로 되돌린다.

## 완료 기준

- 고객 주소가 `client.growthhigh.co.kr/whiffkorea/`에서 바뀌지 않는다.
- 로그인 전에는 위프코리아 정보가 전달되지 않는다.
- 고객 비밀번호와 담당자 Google 로그인이 모두 동작한다.
- 제로백과 기존 공개 페이지는 이전과 동일하게 열린다.
- 홈페이지와 다우오피스 메일 송수신에 영향이 없다.
- 09:00·13:00·18:00 비공개 갱신이 계속 성공한다.

## 실제 변경 전 승인 지점

Cloudflare에 도메인을 추가하는 것은 아직 실서비스를 바꾸지 않는다. 그러나 이후
Cloudflare가 DNS를 관리할 준비를 만드는 보안 관련 변경이므로 사용자 확인 후 진행한다.
네임서버 변경은 홈페이지·메일·모든 하위 주소에 영향을 줄 수 있으므로 별도로 한 번 더
확인받고 실행한다.
