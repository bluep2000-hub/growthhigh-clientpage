# 위프코리아 자체 도메인 전환 계획

기준일: 2026-09-19

## 결론

회사 전체 네임서버는 옮기지 않는다. 기존 DNS에서 `client.growthhigh.co.kr`
CNAME 한 줄만 Cloudflare Pages로 바꾼다.

- `/whiffkorea/*`: Pages Function이 비공개 Worker에 내부 전달한다.
- `/zeroback/*`와 다른 고객사: Pages가 저장소의 기존 정적 화면을 그대로 제공한다.
- 홈페이지·메일·뉴스레터·`www`·`blog`·`dashboard`: 변경하지 않는다.

GitHub Pages 원본을 중계하는 방식은 쓰지 않는다. GitHub 원본이 다시 `client`
주소로 돌려보내 무한 반복이 생기는 것을 실제 응답으로 확인했다.

## 현재 값과 복구 값

| 구분 | 값 |
|---|---|
| 네임서버 | `cns1.hostcocoa.com` ~ `cns4.hostcocoa.com` 유지 |
| 현재 고객페이지 | `client.growthhigh.co.kr` → `bluep2000-hub.github.io` CNAME |
| 전환 대상 | `client.growthhigh.co.kr` → `growthhigh-clientpage-gateway.pages.dev` CNAME |
| 즉시 복구 | `client` CNAME을 `bluep2000-hub.github.io`로 되돌림 |
| 검수 주소 | `https://growthhigh-clientpage-gateway.pages.dev` |

Cloudflare에 만들어 둔 비활성 `growthhigh.co.kr` 영역과 배정 네임서버는 사용하지
않는다. 등록 기관의 네임서버도 바꾸지 않는다.

## 배포 구조

`scripts/build_pages.mjs`가 공개에 필요한 파일만 `pages-dist/`에 모은다.

- 포함: 기존 고객사 HTML, 암호화된 고객사 자료, 공용 이미지·로고, 404 화면
- 제외: `docs`, `src`, `worker`, 과거 `c/whiffkorea.enc`, 위프코리아 정적 사본
- `_routes.json`: `/whiffkorea`와 그 아래 주소만 Function을 실행한다.
- `functions/whiffkorea/[[path]].js`: 외부 출처 요청을 차단하고 기존 비공개
  Worker에 요청 방식·본문·쿠키를 그대로 전달한다.

`main`에 변경이 올라오면 `.github/workflows/pages-gateway.yml`이 공개 파일을 다시
만들고 검사한 뒤 Pages에 배포한다. 따라서 기존 `rebuild.yml`이 제로백 등 고객사
산출물을 갱신해 push하면 Pages에도 자동 반영된다. 위프코리아의 09:00·13:00·18:00
비공개 갱신은 기존 Worker/D1 흐름을 그대로 사용한다.

## 2026-09-19 검수 결과

- 검수용 Pages 프로젝트 `growthhigh-clientpage-gateway` 생성·배포 완료.
- 제로백 HTML과 공용 로고가 저장소 산출물과 바이트 단위로 동일함을 확인했다.
- 실제 위프코리아 고객 비밀번호 로그인, 전체 화면, 모바일 메뉴, 기업정보,
  공지사항, 소통 내역, 데이터룸, 로그아웃 후 차단을 확인했다.
- 담당자 Google 로그인 화면과 challenge·nonce 쿠키 생성을 확인했다.
- 잘못된 비밀번호는 401, 외부 출처 요청은 403, 로그인 전 고객 본문은 401이다.
- `c/whiffkorea.enc`, `worker`, `docs`, `src` 요청은 모두 404다.
- 전체 Worker 검사 29개 파일·335개와 Pages 게이트웨이 검사가 통과했다.

## 남은 전환 순서

1. Cloudflare Pages 배포 전용 API 토큰을 만들고 GitHub 저장소 비밀값
   `CLOUDFLARE_API_TOKEN`으로 저장한다.
2. 저장소 변경사항을 `main`에 push하고 자동 배포 성공을 확인한다.
3. 가능하면 `client` CNAME TTL을 먼저 낮추고 기존 TTL 1시간을 기다린다.
4. Pages에 `client.growthhigh.co.kr` 사용자 도메인을 등록한다.
5. 기존 DNS에서 `client` CNAME 한 줄만 Pages 주소로 바꾼다.
6. 위프코리아 고객·담당자 로그인, 제로백, 자동 갱신을 확인한다.
7. 문제가 있으면 `client` CNAME을 GitHub Pages 값으로 되돌린다.

## 실제 변경 전 승인 지점

- 최소 권한 Cloudflare API 토큰 생성 및 GitHub 비밀값 저장
- `client.growthhigh.co.kr` CNAME 실제 변경

두 작업은 각각 사용자 확인을 받은 뒤 실행한다. 회사 전체 네임서버 변경은 이
계획에 포함하지 않는다.
