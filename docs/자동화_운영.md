# 통화·미팅 기록 자동 적재 — 운영 문서

녹음 → 전사 → 요약 → 노션 → 클라이언트 페이지까지 **하루 세 번**
(9시 · 15시 · 19시) 자동으로 돈다. 스케줄러가 파이썬이 아니라 **클로드 예약
세션**인 이유는, 요약(talk-summary)이 스킬이고 미분류 파일을 본문 보고
판단하는 단계가 있기 때문이다.

## 지금 켜는 것과 안 켜는 것

**전사는 결제 전까지 쓰지 않는다.** 무료 등급은 보낸 내용을 구글이 학습에
쓰고 사람이 검토할 수 있다. 기업 통화가 거기로 새면 안 된다. 결제 연결은
v1 완성 후로 정했다.

그래도 **예약 세션은 지금 켠다.** v1 이 끝나기 전에는 새 녹음이 들어오지
않으므로 전사 단계는 매 회차 「새 녹음 없음」으로 조용히 지나간다. 나머지 —
메일·노션·캘린더를 모아 빌드하고 배포하는 부분 — 은 제미나이를 쓰지 않는다.
페이지를 최신으로 유지하는 일의 대부분이 여기다. 소통 내역 46건 중 녹음에서
온 것은 2건뿐이다.

전사기 자체는 2026-09-03 에 검증했다. 1분 8초 통화를 누락 없이 받아썼고
화자 구분도 끝까지 일관됐다. 그때 쓴 녹음은 새어도 되는 내용으로 골라 둔 것이었다.

켜는 순서:
1. 아래 지시문으로 예약 세션 등록 (`0 9,15,19 * * *`)
2. 등록 직후 한 번 수동 실행해 결과를 옆에서 본다
3. 다음 회차는 손대지 말고, 노션 「마지막 빌드」가 갱신됐는지만 본다
4. (v1 완성 후) https://aistudio.google.com/app/apikey 에서 키에 결제 계정 연결

**예약 세션은 한 대에서만 돌린다.** 두 대에서 돌리면 두 가지가 깨진다.
전사 기록(`.transcribed.json`)이 기계마다 따로라 같은 녹음을 두 번 전사하고,
빌드 산출물(`c/*.enc`)은 빌드할 때마다 바이트가 달라 git 이 매번 충돌한다.
계정이 같아도 소용없다 — 둘 다 그 PC 의 디스크에 있는 것이라 따라오지 않는다.
**회사 PC 한 대**로 정했다.

**예약 세션은 앱이 열려 있을 때만 돈다.** 꺼져 있으면 다음에 켤 때 밀린
회차가 한 번 돈다. 그래서 「9시」는 실은 「9시 이후 앱을 처음 켤 때」다.

## 스킬 동기화 — PC 마다 한 번

3단계에서 부르는 talk-summary 스킬은 `skills/talk-summary/SKILL.md` 에 있다.
클로드는 이 자리를 읽지 않으므로 PC 마다 복사해야 쓸 수 있다.

```bash
mkdir -p ~/.claude/skills/talk-summary
cp skills/talk-summary/SKILL.md ~/.claude/skills/talk-summary/
```

`git pull` 로 SKILL.md 가 바뀌었으면 다시 복사한다.
**복사를 잊으면 그 PC 는 옛 규칙으로 돈다** — 채널값이 노션에 없어 기록이
실패하거나, 중복키가 달라 같은 미팅의 회의록이 두 개 생긴다.

## 예약 세션 지시문 (그대로 붙여넣는다)

```
그로스하이 클라이언트페이지 — 통화·미팅 기록 적재.
작업 폴더: <이 지시문을 등록하는 PC 의 레포 경로를 여기에 적는다>

0. 최신 상태로 맞추기
   git pull --rebase
   충돌이 나면 여기서 멈추고 보고한다. 혼자 풀지 않는다.

1. 새 녹음 전사
   python src/transcribe_drive.py
   "전사할 새 녹음본이 없다" 가 나오면 여기서 끝낸다. 한 줄 보고하고 종료.

2. 미분류 정리
   드라이브 폴더에 *_미분류_*.txt 가 있으면 본문을 읽고 어느 기업인지 정한다.
   노션 「공유페이지」 DB에 있는 기업 중에서만 고른다. 목록에 없는 이름은 쓰지 않는다.
   확실하면 260903_위프코리아_통화.txt 형태로 파일 이름을 고친다.
   애매하면 그대로 두고 보고에 적는다. 지어내지 않는다.

3. 요약을 노션에 기록
   talk-summary 스킬을 호출한다.

4. 클라이언트 페이지 갱신
   python src/publish.py --client whiffkorea

   새 녹음이 없어도 실행한다. 메일·노션·일정이 바뀌었을 수 있다.
   내용이 안 바뀌었으면 이 명령이 알아서 커밋하지 않는다.

   0 이 아닌 코드로 끝나면 거기서 멈추고 출력을 그대로 보고한다.
   pull 충돌·사본 갈라짐·평문 경고·산출물 아닌 파일 변경이 원인이다.
   혼자 풀지 않는다.

5. 보고 (3줄 이내)
   전사 N건 / 노션 기록 N건 / 배포 N곳 / 미분류로 남은 파일 이름
```

1번에서 「새 녹음 없음」이 나와도 **4번은 반드시 실행한다.** 여기서 끝내면
그날 노션에 적은 것과 새로 온 메일이 페이지에 반영되지 않는다.

## 사람이 하는 일

컨설턴트가 녹음하고, 녹음 파일을 구글드라이브 「클라이언트 통화 미팅기록」
폴더에 올린다. 그게 전부다. 파일 이름은 손대지 않아도 된다.

이름을 손댈 수 있다면 `[위프코리아]` 처럼 대괄호로 기업명을 넣어 두면
전사기가 바로 알아본다. 안 넣어도 요약 단계에서 본문 보고 정한다.

## 문제가 생기면

| 증상 | 원인과 조치 |
|---|---|
| `폴더를 못 찾았다` | 구글 드라이브 데스크톱이 꺼져 있다. 켠다 |
| `GEMINI_API_KEY 가 없다` | `.env` 확인 |
| 같은 녹음이 다시 전사된다 | `.transcribed.json` 이 지워졌다. 이 파일이 처리 기록이다 |
| `미분류` 가 계속 쌓인다 | 파일 이름에 `[기업명]` 을 넣도록 컨설턴트에게 안내 |
