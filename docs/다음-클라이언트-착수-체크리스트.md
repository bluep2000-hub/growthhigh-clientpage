## 메일 연결 완료 기준 (2026-09-23 보강)

- IMAP 검색 성공이나 메일 원본 DB 저장만으로 완료 처리하지 않는다.
  `sync_mails_to_board` 이후 실제 커뮤니케이션보드의 기업명·메일 채널·고객 공개·본문을 확인한다.
- 공유페이지 소통 연결 보기를 새로고침하고 같은 메일이 표시되는지 확인한다.
  보이지 않으면 원본 행과 보기 필터를 대조한다. 이미 있는 행을 다시 만들지 않는다.
- 고객페이지에서 실제 메일을 펼쳐 원문 개행이 유지되는지 확인한다.
  제목과 건수만 확인하고 본문 검수를 생략하지 않는다.
- 원본이 표인 메일은 항목·상세내용의 열 관계까지 확인한다. 개행 개수나 CSS 설정만으로
  가독성 검수를 통과시키지 않는다. HTML 본문을 우선 읽고 단순 데이터 표는 Notion 표로 저장한다.
  일반 텍스트만 있는 메일은 그대로 유지한다. 기존 PM 수정 본문은 자동 덮어쓰지 않는다.
- `worker/test/mail-layout.test.js`는 보울게임즈·담은결·미래 고객 이름으로 같은 줄바꿈 처리를 검사한다.
  `src/tests/test_mail_fallback.py`는 HTML 메일 개행과 보드 저장·중복 방지를 검사한다.
- 비공개 빌드는 IMAP을 건너뛰고 보드를 읽는다. 신규 고객의 과거 메일 수집·보드 동기화가
  별도로 완료됐는지 확인하며, 빌드 성공을 메일 수집 성공으로 간주하지 않는다.

로드맵 표의 필수 열은 `시기`, `실행 항목`, `주요 성과 / 산출물`, `비고`다.
현재 파서는 `'26년 9월` 같은 시기를 읽는다. 참고 문구는 화면에 다시 노출하지 않는다.
없는 일정을 만들거나 보울게임즈 사업명·산출물을 다른 고객에 복사하지 않는다.

## 비공개 빌드와 배포 구분

캘린더는 ICS 연결 성공뿐 아니라 실제 제목 형식을 확인한다. `[기업명] 미팅`과
`[문의]N2 기업명 - 담당자`, `[정기미팅]기업명-담당자` 형식을 지원한다.
접두어 뒤 기업명은 정확한 이름과 경계가 맞아야 하며, 다른 기업 일정의 본문 언급은 연결하지 않는다.
`[취소]` 또는 ICS `STATUS:CANCELLED` 일정도 표시한다. 제목과 상태에 취소를 명시하고
임박 일정으로 강조하지 않는다. 조회 기간은 오늘부터 90일이며 과거 일정은 현재 조회 범위 밖이다.

등록과 인증 설정을 확인한 다음 운영 저장소 루트에서 대상 하나만 실행한다.

```powershell
node worker/scripts/build-private.mjs --client=<확정한-영문주소>
```

실제 고객 데이터는 비공개 D1에 저장한다. 과거 `publish.py` 정적 배포 절차를
신규 비공개 고객 데이터 배포에 그대로 사용하지 않는다. 화면 코드를 바꿨다면
`worker/wrangler.private.toml`을 사용하는 고객 전용 Worker 배포도 별도로 필요하다.
문서만 변경한 경우 서비스 재배포는 필요 없다.
