# 위프코리아 로그인 연결 검수 — 2026-09-19

기업 배포 작업을 이어서 진행했다. 기존 UI·공지·즐겨찾기·자료 반영 요청·녹음 흐름은 변경하지 않았다.
이 문서는 `HANDOFF-20260918-기업배포.md`의 Google 설정 및 로그인 화면 상태만 갱신한다.

## 완료된 작업

- 기존 PC에서 옮긴 `.env`, `worker/.dev.vars`의 위치를 바로잡았다. 기존 AUTH_PEPPER 일치를 확인했으며 새 인증값은 만들지 않았다.
- Google `growthhigh-client` 프로젝트에서 기존 데스크톱 앱과 구별되는 웹 앱 `GrowthHigh Clientpage Web`을 만들었다.
- 허용 웹 출처는 `https://client.growthhigh.co.kr`, `http://localhost`, `http://localhost:8787`이다. 인증에는 기본 신원 확인만 사용하며 메일·Drive 권한을 추가하지 않았다.
- 공개 설정값 GOOGLE_CLIENT_ID와 APP_ORIGIN을 `worker/wrangler.private.toml`에 연결했다. 클라이언트 secret은 사용·보관하지 않는다.
- `/whiffkorea/`에 고객 비밀번호 검수 화면, `?edit`에 담당자 Google 검수 화면을 연결했다. 실제 고객 데이터를 포함하지 않는 인증 검수용 화면이다.
- 기존 API의 고객/내부 쿠키 분리, Google nonce 및 서명 검증, Notion 역할·담당 기업 확인을 재사용한다.
- 인증된 담당자 세션이 만료되면 Google 재확인을 시도하며 공식 로그인 버튼을 대안으로 유지한다. 실제 Google 갱신 성공은 아직 미확인이다.
- 처음 접속하거나 로그아웃한 사용자는 주기 검사 때문에 불필요한 재로그인 오류나 자동 팝업이 뜨지 않는다.
- 로컬 별도 DB에만 스키마와 기존 비밀번호 확인값을 연결했다. 원격 비밀번호·고객 데이터는 변경하지 않았다.

## 검증 근거

- `worker`에서 `npm test`: 25개 파일, 324개 검사 통과.
- `npm audit --omit=dev`: 운영 의존성 취약점 0건. 개발 의존성 경고는 별도이며 강제 업그레이드하지 않았다.
- 실제 Notion 조회와 Google 로그인 후 화면에서 등록된 대표 계정의 대표/위프코리아 권한 확인.
- 로컬 서버에 기존 비밀번호로 실제 로그인 → 인증 쿠키 확인 → 로그아웃 → 이전 쿠키 거부 모두 통과. 원문 비밀번호와 쿠키는 출력하거나 파일에 저장하지 않았다.
- 고객 데이터 경로는 로그인 후에도 404로 닫혀 있다. 이는 데이터 연결 전 안전 상태이며 기업 배포 완료가 아니다.
- UI detector 결과 0건, `git diff --check` 통과. 담당자 데스크톱 화면과 공식 Google 버튼 렌더 확인.

## 진행 중 / 아직 미확인

Google 공식 버튼으로 계정 선택 창까지 열렸지만 해당 팝업의 자동 조작이 응답하지 않았다.
사용자가 직접 등록된 대표 계정을 선택한 뒤 실제 화면에 ‘로그인 확인 완료 / 대표 · 위프코리아’가 나타나는 것을 확인했다.
앱 설정, Google 증명 확인, 서버 세션과 Notion 권한 확인이 실제로 연결됐다. 실제 토큰·쿠키·인증 URL은 기록하지 않는다.

- Google 실제 로그인·서버 권한 확인 완료. 실제 담당자 로그아웃·갱신 검수는 남아 있다.
- 모바일 캡처와 독립 UI 마감 검수 미완료. 자동 검사 통과를 UI 마감 승인으로 해석하지 않는다.
- Google 동의 화면은 기존 외부/테스트 상태를 유지한다. 개인정보처리방침 등 사실 확인 없이 앱 게시 또는 테스트 사용자 확대를 하지 않는다.
- 실제 고객용 데이터 투영·빌더 갱신·내부 편집 API 연결·운영 주소 전환 미완료.
- 현재 PC 녹음 예약은 비활성이다. 기존 PC 중지 및 처리 장부 이전 전에는 활성화하지 않는다.

## 재개 순서

1. 이 PC의 로컬 검수 주소 `http://localhost:8787/whiffkorea/?edit`에서 등록된 대표 계정으로 로그인 결과를 확인한다.
2. 고객/담당자 화면과 로그인·로그아웃·권한 제거·Google 재인증을 검수한다. 인증 없는 고객 데이터 전달은 계속 차단한다.
3. 고객 데이터 투영과 기존 갱신 흐름을 연결하고 검증한 다음에만 운영 주소 전환을 진행한다.

로컬 실행: `worker`에서 `npx wrangler dev --config wrangler.private.toml --ip 127.0.0.1 --port 8787 --var APP_ORIGIN:http://localhost:8787 --show-interactive-dev-session=false`.
로컬 DB 검수 준비가 필요한 PC에서만 기존 migration을 `--local`로 적용하고 `node scripts/provision-private-customer.mjs --local`을 실행한다.
새 PC에서도 기존 비공개 환경 파일을 같은 위치에 옮긴다. 비밀값·고객 원문·녹음·전사를 Git에 추가하지 않는다.
