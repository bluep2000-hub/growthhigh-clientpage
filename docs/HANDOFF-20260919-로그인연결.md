# 위프코리아 로그인 연결 검수 — 2026-09-19

기업 배포 작업을 이어서 진행했다. 기존 UI·공지·즐겨찾기·자료 반영 요청·녹음 흐름은 변경하지 않았다.
이 문서는 `HANDOFF-20260918-기업배포.md`의 Google 설정과 로컬 비공개 데이터 연결 상태를 갱신한다.

## 완료된 작업

- 기존 PC에서 옮긴 `.env`, `worker/.dev.vars`의 위치를 바로잡았다. 기존 AUTH_PEPPER 일치를 확인했으며 새 인증값은 만들지 않았다.
- Google `growthhigh-client` 프로젝트에서 기존 데스크톱 앱과 구별되는 웹 앱 `GrowthHigh Clientpage Web`을 만들었다.
- 허용 웹 출처는 `https://client.growthhigh.co.kr`, 새 workers.dev 보안 주소, `http://localhost`, `http://localhost:8787`이다. 인증에는 기본 신원 확인만 사용하며 메일·Drive 권한을 추가하지 않았다.
- 공개 설정값 GOOGLE_CLIENT_ID와 APP_ORIGIN을 `worker/wrangler.private.toml`에 연결했다. 클라이언트 secret은 사용·보관하지 않는다.
- `/whiffkorea/`에 고객 비밀번호 검수 화면, `?edit`에 담당자 Google 검수 화면을 연결했다. 실제 고객 데이터를 포함하지 않는 인증 검수용 화면이다.
- 기존 API의 고객/내부 쿠키 분리, Google nonce 및 서명 검증, Notion 역할·담당 기업 확인을 재사용한다.
- 인증된 담당자 세션이 만료되면 Google 재확인을 시도하며 공식 로그인 버튼을 대안으로 유지한다. 실제 Google 갱신 성공은 아직 미확인이다.
- 처음 접속하거나 로그아웃한 사용자는 주기 검사 때문에 불필요한 재로그인 오류나 자동 팝업이 뜨지 않는다.
- 로컬 별도 DB에만 스키마와 기존 비밀번호 확인값을 연결했다. 원격 비밀번호·고객 데이터는 변경하지 않았다.
- 기존 빌더가 공개 승인한 위프코리아 결과를 메모리에서 바로 비공개 DB로 저장한다. GitHub 산출물이나 공개 `.enc` 파일은 만들지 않는다.
- 큰 본문과 이미지는 Cloudflare 문장 크기 제한을 넘지 않도록 조각 저장한 뒤 완성된 결과만 `ready=1`로 공개한다.
- 로컬 비공개 DB에 정상 결과 1건과 이미지 5건을 저장했고, 임시 조각은 0건으로 정리됐다.
- 기존 원본 화면을 그대로 사용해 기업정보·조달현황·공지·일정·프로젝트·소통·추천·데이터룸을 렌더했다. 상대 이미지 주소도 새 페이지 위치에서 정상 표시된다.
- 공지 초안·게시, 자료 반영 요청·즐겨찾기, 주요 소통 변경을 기존 운영 DB에 연결했다. 위프코리아만 허용하고 모든 변경 요청에서 Google 세션과 Notion 담당 권한을 다시 확인한다.
- 변경 후 GitHub 배포를 부르지 않고 비공개 DB의 갱신 요청을 남긴다. 비공개 화면에서도 GitHub 진행 링크를 제거하고 다음 자동 갱신 기준으로 안내한다.
- 같은 문서의 JSON 필드 순서만 달라 자동저장이 반복되던 오류를 재현 검사로 고치고 실제 화면에서 저장 요청 1회 후 멈추는 것을 확인했다.
- 원격 비공개 DB에 이미지·갱신 요청 migration을 적용하고 공개 승인된 위프코리아 정상 결과를 저장했다. 예약 작업 실전 실행 뒤 기준 정상 결과 3판, 이미지 15건, 대기 요청 0건이다.
- Windows 예약 작업 `GrowthHigh Clientpage Private Refresh`를 09:00·13:00·18:00에 등록했다. 녹음 예약과는 별개이며 중복 실행은 시작하지 않는다. 수동 1회 실전 실행은 결과 코드 0으로 완료됐다.
- 고객 전용 Worker 버전 `ac0f3c06-8340-4156-8c06-4de37b3ba5c6`을 배포했다. 공개 대상은 0개라 운영 주소는 바뀌지 않았다.
- 로그인·페이지 데이터·이미지·편집 API를 모두 `/whiffkorea/` 아래로 묶었다. 사이트 공용 API 경로와 다른 기업 경로는 404로 거절하므로 위프코리아 경로 하나만 새 서버에 연결할 수 있다.
- `/whiffkorea/health`는 비공개 DB의 실제 정상 결과 유무를 확인하며 현재 로컬 검수에서 `ready`를 반환했다.
- 전용 경로 분리본 Worker 버전 `86f60547-f7c1-46c6-9d8e-e18590503a58`을 배포했다. 배포 대상은 여전히 0개이며 운영 주소는 바뀌지 않았다.
- 기존 도메인이 호스트코리아 DNS에서 GitHub Pages로 직접 연결되어 Cloudflare 경로 연결을 사용할 수 없었다. workers.dev 보안 주소를 활성화하고 `APP_ORIGIN`과 Google JavaScript 원본에 등록했다.
- 보안 주소 배포 버전은 `efacefc7-fc2f-433e-9aff-f86efa61f3b6`이다. 실제 대표 Google 로그인, Notion 권한 확인, 위프코리아 전체 화면과 공지 편집 진입을 확인했다.
- 기존 `/whiffkorea/` 정적 화면은 검색값·해시를 유지해 보안 주소로 이동하는 24줄 안내문으로 교체했다. GitHub 재빌드가 위프코리아 공개 파일을 되살리지 않도록 해당 슬러그를 건너뛴다.

## 검증 근거

- `worker`에서 `npm test`: 29개 파일, 333개 검사 통과.
- `npm audit --omit=dev`: 운영 의존성 취약점 0건. 개발 의존성 경고는 별도이며 강제 업그레이드하지 않았다.
- 실제 Notion 조회와 Google 로그인 후 화면에서 등록된 대표 계정의 대표/위프코리아 권한 확인.
- 로컬 서버에 기존 비밀번호로 실제 로그인 → 인증 쿠키 확인 → 로그아웃 → 이전 쿠키 거부 모두 통과. 원문 비밀번호와 쿠키는 출력하거나 파일에 저장하지 않았다.
- 인증 전 고객 화면·본문·이미지는 거절되고, 인증 후에만 같은 판의 본문과 이미지가 열린다.
- 담당자 Google 로그인 뒤 실제 위프코리아 원본 화면과 이미지 렌더를 데스크톱에서 확인했다. 운영 주소는 전환하지 않았다.

## 진행 중 / 아직 미확인

Google 공식 버튼으로 계정 선택 창까지 열렸지만 해당 팝업의 자동 조작이 응답하지 않았다.
사용자가 직접 등록된 대표 계정을 선택한 뒤 실제 화면에 ‘로그인 확인 완료 / 대표 · 위프코리아’가 나타나는 것을 확인했다.
앱 설정, Google 증명 확인, 서버 세션과 Notion 권한 확인이 실제로 연결됐다. 실제 토큰·쿠키·인증 URL은 기록하지 않는다.

- Google 실제 로그인·서버 권한 확인 완료. 실제 담당자 로그아웃·갱신 검수는 남아 있다.
- 모바일 캡처와 독립 UI 마감 검수 미완료. 자동 검사 통과를 UI 마감 승인으로 해석하지 않는다.
- Google 동의 화면은 기존 외부/테스트 상태를 유지한다. 개인정보처리방침 등 사실 확인 없이 앱 게시 또는 테스트 사용자 확대를 하지 않는다.
- 실제 고객용 데이터 투영, 원격 저장, 정기 갱신, 내부 편집 API 연결은 완료. 기존 주소는 새 보안 주소로 자동 이동한다.
- 현재 PC 녹음 예약은 비활성이다. 기존 PC 중지 및 처리 장부 이전 전에는 활성화하지 않는다.

## 재개 순서

1. 고객 비밀번호 로그인과 담당자 로그아웃·재인증을 새 보안 주소에서 운영 확인한다.
2. 모바일 화면을 확인한다.
3. 기존 주소 자동 이동과 다른 고객사 무영향을 관찰한다. 자체 도메인 통합은 DNS 이관을 결정할 때 별도로 진행한다.

로컬 실행: `worker`에서 `npx wrangler dev --config wrangler.private.toml --ip 127.0.0.1 --port 8787 --var APP_ORIGIN:http://localhost:8787 --show-interactive-dev-session=false`.
로컬 DB 검수 준비가 필요한 PC에서만 기존 migration을 `--local`로 적용하고 `node scripts/provision-private-customer.mjs --local`을 실행한다.
새 PC에서도 기존 비공개 환경 파일을 같은 위치에 옮긴다. 비밀값·고객 원문·녹음·전사를 Git에 추가하지 않는다.
