# 추천 지원사업 자동화 — 진행 상태

추천 지원사업을 사람이 손으로 재생목록에 담는 대신, 공고와 기업 양쪽에 업종을
적어 두고 자동으로 좁힌다. 지금은 **낱말을 정하는 단계까지 끝났고, 라벨링은 아직
시작하지 않았다.**

결정의 이유는 [ADR 0002](adr/0002-세부업종-병렬-축.md), 용어는 `CONTEXT.md` 의
「업종」 절을 본다.

## 지금 어디까지 왔나

```
① 노션 정책정보 크롤링 DB   2,981건   자동 수집
        ↓  사람이 선별 + 검토서 제작        ← 여기와
② data-full.json            357건     마지막 갱신 2026-08-16
        ↓  사람이 손으로 슬러그 담기        ← 여기가 손으로 하는 두 자리
③ 재생목록                  기업당 목록
        ↓  자동
④ 클라이언트 페이지
```

②→③ 을 세부업종 교집합으로 대신하는 것이 목표다.

## 확정된 것

**세부업종 16개** — `CONTEXT.md` 「업종」 절에 있다.

**규칙 3개**

```
1. 다중 라벨.  「이 회사가 신청서를 내면 접수되나」로 판정한다
2. 업종 제한이 없는 공고는 비워 둔다 (= 업종 무관 공고)
3. 낱말을 새로 만드는 건 공고 20건 이상에서 자격을 가를 때만
```

**매칭 규칙**

```
공고 세부업종 비어 있음   → 전원에게 추천
공고 세부업종 있음        → 기업 라벨과 하나라도 겹치면 추천
기업 세부업종 비어 있음   → 대분류만 맞으면 추천
```

**커버 범위 메모** — 라벨 붙일 때 헷갈리는 것들

```
농식품 · 수산식품      → 푸드
섬유 · 가죽            → 패션
핀테크                 → ICT·SW
팹리스                 → 반도체/소부장   (반도체 공고가 SoC·SW를 함께 부른다)
온프레미스 · SaaS      → 둘 다 ICT·SW    (납품 방식은 라벨이 아니다)
조선 · 해양플랜트      → 없음. 컨설턴트가 잡는다 (10건이라 기준 미달)
```

「환경」 키워드에는 딴 뜻이 섞인다. **경영환경 개선 · 노동환경개선 · 기업환경 개선**
은 `환경·에너지` 가 아니다.

## 다음에 할 일

**마감 전 공고 448건에 세부업종을 붙인다.** 약 2.5시간.

전수(2,981건)가 아니라 448건인 이유 — 마감 지난 건은 빌드가 이미 제외하고
(`build_client.py` 의 `INCLUDE_EXPIRED = False`), 448건이 오늘 클라이언트
페이지에 오를 수 있는 후보 전부다.

그다음 클라이언트 기업에 라벨을 붙인다. 위프코리아(웰스앤헬스, Whiff 탈취제)는
`라이프` 하나다.

## 아직 안 정한 것

- **빈칸이 두 가지 뜻을 겸한다.** 「업종 무관」과 「아직 안 붙임」이 구분되지
  않는다. 라벨링을 마쳤다는 표시를 어디에 둘지 정해야 한다. 이걸 먼저 정하지
  않으면 라벨링 도중에 손 안 댄 공고가 전원에게 추천된다.
- **라벨을 어느 DB에 적을지.** 노션 크롤링 DB(2,981건)와 `data-full.json`
  (357건)이 `notion_key` 로 이어진 건 145건뿐이다.
- **분류기를 언제 돌릴지.** 크롤링 직후냐, 부를 때냐, 빌드 시점이냐.
  빌드 시점은 「내용이 안 바뀌면 커밋하지 않는다」와 부딪친다.
- **컨설턴트가 「주요 사업」을 어디에 표시할지.** `data-full.json` 의 `curated`
  는 지금 `False` 와 정수 1~13이 섞여 있다.
- **용어 충돌.** `CONTEXT.md` 의 「검토서」는 재생목록 요약 페이지를 가리키는데,
  설계 대화에서는 공고 한 건짜리 HTML을 「검토서」로 부르기로 했다. 둘 중
  하나로 정하고 `CONTEXT.md` 를 고쳐야 한다.

세부업종 16개와 규칙은 확정됐다. 다시 논의하지 마라.
