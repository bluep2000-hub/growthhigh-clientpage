그로스하이 클라이언트페이지 — 통화·미팅 기록 적재와 페이지 갱신.

작업 폴더: C:\Users\FAMILY\Desktop\Claude-work\growthhigh-clientpage
이 폴더에서 실행한다. 아래 순서를 그대로 따른다. 순서를 바꾸지 않는다.

1. 새 녹음 전사
   python src/transcribe_drive.py

   「전사할 새 녹음본이 없다」가 나오면 2·3 을 건너뛰고 4 로 간다.
   GEMINI_API_KEY 가 없다는 오류가 나와도 4 로 간다 — 아직 결제 전이라 정상이다.
   구글 드라이브 폴더를 못 찾으면 드라이브 데스크톱이 꺼진 것이다. 보고하고 4 로 간다.

2. 미분류 정리 (1번에서 새 전사본이 나왔을 때만)
   드라이브 폴더에 *_미분류_*.txt 가 있으면 본문을 읽고 어느 기업인지 정한다.
   노션 「공유페이지」 DB 에 있는 기업 중에서만 고른다. 목록에 없는 이름은 쓰지 않는다.
   확실하면 260903_위프코리아_통화.txt 형태로 파일 이름을 고친다.
   애매하면 그대로 두고 보고에 적는다. 지어내지 않는다.

3. 요약을 노션에 기록 (1번에서 새 전사본이 나왔을 때만)
   talk-summary 스킬을 호출한다.

4. 클라이언트 페이지 갱신 — 새 녹음이 없어도 반드시 실행한다
   python src/publish.py --client whiffkorea

   이 명령 하나가 pull → 사본 검사 → 빌드 → 평문 검사 → 내용 비교 → 배포를 다 한다.
   내용이 안 바뀌었으면 알아서 커밋하지 않고 「갱신 없음 / 배포 0곳」으로 끝난다.

   0 이 아닌 코드로 끝나면 거기서 멈추고 출력을 그대로 보고한다.
   pull 충돌 · 사본 갈라짐 · 평문 경고 · 산출물 아닌 파일 변경이 원인이다.
   무엇도 혼자 풀지 않는다.

5. 보고 — 3줄 이내
   전사 N건 / 노션 기록 N건 / 배포 N곳 / 미분류로 남은 파일 이름
   아무 일도 없었으면 「갱신 없음 / 배포 0곳」 한 줄만 적는다.

반드시 지킬 것
- 위프코리아 한 곳만 배포한다. 다른 슬러그는 v1 이 끝난 뒤에 넓힌다.
- git 명령을 직접 치지 않는다. publish.py 가 pull 과 push 를 다 한다.
- 녹음 원본 파일을 지우거나 옮기지 않는다. 미분류 이름 고치기만 한다.
- 실패한 단계를 우회하려고 다른 명령을 만들어 쓰지 않는다. 멈추고 보고한다.
