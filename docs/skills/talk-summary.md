# 통화·미팅 회의록

클로바노트 녹취를 그로스하이 회의록으로 정리해 클라이언트 페이지에 올린다.

---

## 원천

**구글 드라이브** — 「클라이언트 통화 미팅기록」

```
1EV3Ss6vvv5PUjcR9GtXXGWK36xeTE-I8
```

**노션 소통 내역 DB**

```
DB        3aa815d7-12b9-80f9-ae45-e9f2bebcd9de
data src  collection://3aa815d7-12b9-8038-89a8-000ba370872d
```

**노션 공유페이지 DB** — 클라이언트 릴레이션 대상

```
collection://21e815d7-12b9-8006-83b3-000b0467050f
```

---

## 파일명 규칙

```
YYMMDD_기업명_채널.txt

260724_위프코리아_미팅.txt
260723_위프코리아_통화.txt
```

기업명은 공유페이지 DB의 「페이지명」이 아니라 **기업 DB의 기업명**과 대조한다.
채널은 `미팅` 또는 `통화`. 확장자는 `.txt` 또는 `.md`.

규칙에 안 맞는 파일은 **건너뛰고 보고에 남긴다. 추측하지 않는다.**

---

## 절차

### 1. 폴더 훑기

파일 목록을 가져온다. 이름과 **파일 ID**를 기록한다.

전사본에 짝이 되는 오디오 원본이 있으면 **그 오디오의 파일 ID**도 함께 기록한다.
짝은 전사기가 남긴 `.transcribed.json`(오디오 파일명 → 전사본 stem)으로 잇는다.
파일명이 비슷하다고 짝으로 묶지 않는다.

### 2. 이미 처리한 것 걸러내기

노션 소통 내역 DB에서 기존 `Message-ID` 값을 전부 받는다.

중복 키는 이렇게 정한다.

| 상황 | 키 |
|---|---|
| 오디오 원본이 있다 (제미나이 전사본) | **오디오 파일 ID** |
| 오디오 원본이 없다 (사람이 올린 전사본) | **전사본 파일 ID** |

키가 이미 노션에 있으면 그 파일은 건너뛴다.

오디오 쪽을 쓰는 이유는 전사 직후 전사본이 아직 드라이브에 업로드되지 않아
파일 ID가 없기 때문이다. 오디오는 컨설턴트가 올린 순간부터 ID가 있다.

파일명이나 날짜로 대조하지 않는다 — 같은 날 같은 기업과 두 번 만날 수 있다.

### 3. 클라이언트 찾기

파일명의 기업명으로 공유페이지 DB에서 클라이언트 행을 찾는다.
`페이지 유형`에 `👨‍💼클라이언트페이지`가 있고, 연결된 기업 DB의 기업명이 일치하는 행.

**정확히 일치하는 행이 없으면 건너뛴다.** 비슷한 이름으로 추측하지 않는다.

### 4. 회의록 작성

이게 이 스킬의 본체다. **요약이 아니라 회의록이다.**
1시간 미팅이면 안건이 대여섯 개 나온다. 각 안건의 배경·논의·결론을 다 담는다.

#### 구조

```markdown
## 1. 제품 기술 방향성 논의

**현황 및 문제인식**

- 기존에 기성 제조사 기술을 가져오는 방향으로 진행했으나, 적용 가능한 기술의 범위가 협소한 문제 확인
- 여러 특허사무소(3~5곳)와 소통 중이나, 요구사항에 정확히 맞는 피드백이 부족한 상황

**결론 및 방향 전환**

- 기성 기술 도입 → **랩(연구실)과의 원천 공동개발**로 방향 전환 검토
- 기술 계약 시 **착수금 50% + 완료 시 잔금** 구조로 진행 예정

---

## 2. 자금조달 현황 보고

**신보(신용보증기금) 관련**

- 사업자 변경 관련 이슈: 현재 대표자 교체가 아닌 **추가 등재** 방식 권고
    - 이유: 대표자 교체 시 자금조달 불이익 우려
- 어머님 명의 부동산 보유 여부 확인 요청 → "없다"고 확인됨

---

## 3. 향후 일정 및 Action Items

| 항목 | 담당 | 기한 |
| --- | --- | --- |
| 광주 물건지 임차 조건 상세 확인 | 그로스하이 | 다음 미팅 전 |
| 제조사 M&A 구체 스펙 정리 후 공유 | 클라이언트 | 이달 내 |
```

#### 작성 규칙

**섹션** — `## N. 안건명` 으로 번호를 붙인다. 안건 사이에 `---` 를 넣는다.
안건 순서는 녹취에 나온 순서를 따른다. 중요도로 재배열하지 않는다.

**소제목** — 각 안건 안에서 `**현황 및 문제인식**`, `**결론 및 방향 전환**`,
`**진행 상황**`, `**계약 조건 전략**` 처럼 내용에 맞게 붙인다.
정해진 목록이 없다. 그 안건에 맞는 말로 쓴다.

**불릿** — 한 줄에 하나의 사실. 필요하면 들여쓰기로 근거·부연을 단다.

```
- 사업자 변경 관련 이슈: 대표자 교체가 아닌 추가 등재 방식 권고
    - 이유: 대표자 교체 시 자금조달 불이익 우려
```

**강조** — 결론·핵심 조건·전환점에 `**볼드**`. 남발하지 않는다.

**표** — 비교 대상이 셋 이상이면 표로 만든다. 지역별 비교, 조건별 비교 등.

**마지막 섹션은 항상 Action Items** — `| 항목 | 담당 | 기한 |` 표.
담당은 `그로스하이` 또는 `클라이언트`.
기한은 녹취에 나온 대로. 안 나왔으면 `미정`.

#### 반드시 지킬 것

- **숫자·금액·지역명·기관명은 원문 그대로.** 어림하거나 반올림하지 않는다
- **원문에 없는 내용을 만들지 않는다.** 맥락상 그럴 것 같아도 안 쓴다
- 결론이 안 난 안건은 「추가 검토 필요」로 남긴다. 결론을 지어내지 않는다
- 인사말·잡담·중복 발언은 뺀다
- 발언자를 적지 않는다. 「대표님이 말하길」 같은 표현 대신 내용만 쓴다
- 녹취 오인식으로 보이는 단어는 원문 표기를 살리되, 명백한 오타는 바로잡는다

#### 고유명사는 노션과 대조한다

녹취는 사업명·기관명을 자주 틀리게 받아쓴다. 1분짜리 통화에서도 난다.
회의록을 쓰기 전에 노션에서 정식 명칭을 찾는다.

| 대상 | 대조할 곳 |
|---|---|
| 사업명 | 프로젝트 DB 의 「프로젝트명」, 기업 DB 의 관심정책사업 |
| 기업명 | 기업 DB 의 「기업명」 |
| 인증·특허명 | 기업 DB 의 「인증ㅣ특허」 |

찾으면 **정식 명칭으로 적는다.** 못 찾으면 원문 표기를 그대로 둔다.
비슷하다고 골라 넣지 않는다.

```
녹취    "소 소공 소상공인 판 판매 개척"
노션    「2026년 소공인 판로개척 지원사업(트랙II)」
회의록   소공인 판로개척 지원사업
```

**금액·날짜·수치는 대조 대상이 아니다.** 녹취에서 들린 그대로 옮긴다.
노션에 적힌 숫자와 달라도 녹취를 따른다 — 그 자리에서 정정된 값일 수 있다.

#### 제목

목록에 보일 짧은 제목을 따로 만든다. **25자 이내.**
그날 다룬 것 중 가장 큰 안건이나, 여러 개면 포괄하는 말로.

```
기술 방향·자금조달·M&A 검토
수출바우처 서류 협의
```

---

### 5. 노션에 기록

**속성**

| 속성 | 값 |
|---|---|
| 제목 | 만든 제목 (25자 이내) |
| 클라이언트 | 3번에서 찾은 클라이언트 페이지 (릴레이션) |
| 일자 | 파일명의 YYMMDD → `20YY-MM-DD` |
| 채널 | `미팅` 또는 `통화` |
| 방향 | 비움 |
| 요약 | **안건 목록 한 줄** — `제품 기술 방향성 · 자금조달 · 제조사 M&A · 부동산 임장` |
| Message-ID | **2번에서 정한 키** (오디오 원본 ID, 없으면 전사본 ID) |
| 상태 | `공개` |

**본문**

회의록 전체를 **페이지 본문**에 넣는다. 마크다운 그대로 노션 블록으로.
`요약` 속성은 rich_text 2000자 제한이 있고 표를 담을 수 없으므로 본문에 쓴다.

`요약` 속성에는 안건명만 `·` 로 이어 적는다. 목록 화면에서 그날 뭘 다뤘는지
한눈에 보이게 하는 용도다.

## 주의

**회의록이 그대로 클라이언트에게 나간다.** 검토 단계가 없다.
확실하지 않으면 쓰지 않는다. 추측해서 채우지 않는다.

**원본 파일은 건드리지 않는다.** 읽기만 한다. 이름을 바꾸거나 옮기거나 지우지 않는다.

**한 번에 20건까지.** 넘으면 오래된 것부터 20건만 하고 보고에 남긴다.
