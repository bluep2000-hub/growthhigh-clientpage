# 같은 이름의 고객 녹음 보존 설정

2026-10-08 사용자 `둘 다 했어` 답변으로 통화 업로드·고객 미팅 업로드 두 FolderPair에 아래 설정을 적용했다고 확인했다. 별도 화면 확인 또는 동일 이름 원본의 실제 폰 보존 검증을 의미하지는 않는다. 반복 녹음 테스트 없이 다음 실제 업무 녹음에서 전체 처리를 확인한다.

입력 이름은 그대로 `YYMMDD_고객사_통화` / `YYMMDD_고객사_미팅`이다. 시간이나 번호를 직접 입력하지 않는다.
갤럭시가 같은 이름에 `(1)`을 자동으로 붙이는지는 아직 사용자 확인 전이다. 서버는 해당 자동 접미사를 읽을 수 있다.
휴대폰에서 이미 덮어쓴 녹음은 서버에서 복구할 수 없다.

## 휴대폰에서 한 번만 설정

FolderSync의 **통화 업로드**와 **고객 미팅 업로드** 각각을 열고 **동기화 설정**에서 다음과 같이 저장한다.

1. **기존 파일 덮어쓰기**: `덮어쓰지 않음` / `Never`에 해당하는 항목.
2. 아래쪽 **정렬 설정 → 대상 폴더 내 파일 정렬**: `파일 수정 시각` / `Last modified`에 해당하는 항목.
3. **폴더명 형식 (날짜, 시간)**: `yyyyMMdd_HHmmss_SSS`.
4. **임시 파일 사용** 켬. **삭제 상태 동기화**, **파일 전송 후 원본 파일 삭제**, **파일을 대상 폴더로 이동**은 끔.
5. **파일을 Time-stamp 폴더로 복사**는 끔. 이 백업 옵션은 동기화마다 모든 파일을 다시 복사하므로 사용하지 않는다.

예약 15분, Wi-Fi·모바일 연결 허용, 배터리 최적화는 기존 설정을 유지한다. 원격 기본 폴더도 `/upload`다.
이 설정은 앱이 전송 경로를 자동 구분하는 용도이며, 수정 시각을 실제 통화 시작 시각으로 사용하지 않는다.

**필터**는 포함 / **파일 이름 정규표현식**으로 저장한다. 기존 내부 미팅 필터는 유지한다.

통화:

```text
^[0-9]{6}_[^_]+_통화(?: \([1-9][0-9]{0,2}\))?\.m4a$
```

고객 미팅:

```text
^[0-9]{6}_[^_]+_미팅(?: \([1-9][0-9]{0,2}\))?\.m4a$
```

서버가 고객사 등록 여부와 날짜를 다시 검사한다. 등록되지 않은 고객이나 라벨이 없는 녹음은 고객 게시하지 않는다.

## 보존 흐름과 확인 범위

앱은 파일 수정 시각에 따라 `/upload/20261008_101010_123/261008_위프코리아_통화.m4a`처럼 전송한다.
서버는 기존 평면 경로와 이 날짜 폴더 한 단계를 모두 읽는다. 내용이 다른 같은 이름은 보관본만 `_2`, `_3`으로 구분하며 원본을 삭제하지 않는다. 같은 내용의 재전송은 SHA256으로 중복 처리하지 않는다.
같은 경로가 다시 생기면 덮어쓰지 않도록 설정한다. 수정 시각까지 같은 충돌은 새 전송이 건너뛰어질 수 있으므로 동기화 내역에서 확인해야 한다.

공식 문서는 정렬 기능을 실험 기능으로 표시하고, 서로 다른 원본 경로의 동일 파일명 충돌은 주의하라고 안내한다. 따라서 휴대폰 설정 저장만으로 보존 전체 검증이 끝났다고 표현하지 않는다. 다음 실제 업무 녹음 때 자동 번호 처리와 전송 내역을 함께 확인한다. 별도의 반복 녹음 테스트는 요구하지 않는다.

근거: [FolderSync 공식 설정 문서 — 덮어쓰기·임시 파일·정렬·백업](https://foldersync.io/docs/help/v2/folderpairsettings/).

고객별 Notion 원본 링크는 서버가 실제 Drive 고객 접수 폴더 ID를 조회해서 만든다. 폴더가 없거나 같은 고객 이름이 둘 이상이면 임의로 고르지 않고 처리를 중단한다.
