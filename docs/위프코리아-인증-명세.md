# 위프코리아 비공개 서버 인증

2026-09-18. 기업 배포 계획의 2차 작업. 기존 공개 페이지의 인증은 아직 변경하지 않았다.
이 문서는 새 연결만 다룬다. 고객 UI·자료 갱신·운영 주소 연결은 이후 작업이다.

## 사용자·경계·상태

고객은 기업 비밀번호 하나로 고객 읽기 세션을 만든다. 개인 회원가입·이메일 인증은 없다.
PM·대표는 Google 인증과 Notion의 내부 등록·역할·담당 기업을 모두 확인한다.
고객 세션·기존 담당자 공용 토큰·자동화 토큰은 새 서버의 관리 권한이 아니다.

미인증 → 인증 처리 → 고객 또는 내부 세션.
입력 오류·인증 실패·다른 기업·담당 범위 없음·외부 인증 장애·설정 미완료를 구분한다.
현재 고객 화면은 아직 연결되지 않았으므로 건강 확인의 `customerReady`는 계속 false다.
새 API로 기업 정보·공지 초안·Notion 원본·비밀번호 원문을 내려주지 않는다.

## API

모든 응답은 JSON이며 `Cache-Control: no-store`를 사용한다.
쓰기 요청은 같은 출처의 `Origin`과 JSON 본문을 요구한다.
`APP_ORIGIN`이 미설정이면 쓰기는 503으로 차단한다. 외부 출처는 403이다.
브라우저 요청은 같은 서버에서 `credentials: "same-origin"`으로 호출한다.
쿠키에는 `Secure; HttpOnly; SameSite=Strict; Path=/`를 사용하며 Domain은 지정하지 않는다.

| 요청 | 입력·기능 | 성공 응답 |
|---|---|---|
| POST `/auth/customer/login` | `{slug:"whiffkorea", password}` | `{authenticated:true, slug}` + 고객 쿠키 |
| GET `/auth/customer/session` | 고객 쿠키 검증 | `{authenticated:false}` 또는 `{authenticated:true, slug}` |
| POST `/auth/customer/logout` | 이 기기 고객 세션 삭제 | `{authenticated:false}` + 쿠키 삭제 |
| POST `/auth/staff/challenge` | 일회용 Google nonce 생성 | `{nonce, clientId}` + nonce 쿠키 |
| POST `/auth/staff/login` | `{credential}` (Google ID token) | `{authenticated:true, role, slug}` + 내부 쿠키 |
| GET `/auth/staff/session` | 내부 쿠키·Google 증명 유효기간·Notion 권한 확인 | `{authenticated:true, role, slug}` |
| POST `/auth/staff/logout` | 이 기기 내부 세션 삭제 | `{authenticated:false}` + 쿠키 삭제 |
| POST `/auth/customer/password` | 내부 세션으로 `{slug, password}` | `{changed:true, slug}`. 기존 고객 전 기기 세션 종료 |

본문 스트림은 16KiB, 비밀번호 UTF-8은 1KiB까지 받는다.
고객 비밀번호는 변형·공백 제거 없이 기존 값을 그대로 확인한다.
이관 시 Notion 원본을 읽을 때만 기존 빌더 `p_text`와 같은 앞뒤 공백 제거 규칙을 적용한다.
잘못된 비밀번호는 401, 형식·다른 기업은 422, 과대 본문은 413,
잘못된 메서드는 405, Notion 연결 실패는 502다. 상세 upstream 오류는 출력하지 않는다.

## 데이터·보호

기존 고객 DB 안에 `customer_credentials`, `customer_sessions`, `staff_sessions`,
`staff_login_nonces`, `auth_request_buckets`를 추가한다. 기존 공지 DB는 변경하지 않는다.

- 비밀번호는 임의 salt와 PBKDF2-HMAC-SHA256 100,000회로 처리하고,
  DB 밖 `AUTH_PEPPER` secret을 이용한 HMAC 결과만 저장한다.
- Workers의 [공식 실행 엔진 소스](https://github.com/cloudflare/workerd/blob/main/src/workerd/io/limit-enforcer.h)는
  기본 PBKDF2 상한을 100,000회로 정한다. 이는 [OWASP의 PBKDF2 권장 횟수](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#pbkdf2)보다 낮다.
  권장 횟수를 충족했다고 쓰지 않는다. 외부 secret의 pepper와 요청 제한을 함께 적용한다.
- Pepper를 잃거나 바꾸면 기존 확인값을 검증할 수 없으므로 복구·교체 절차를 운영 검수에서 다룬다.
  기존 공지·자동화 인증값과 구분하며 임의로 회전시키지 않는다.
- 원문 비밀번호·Google ID token·세션 토큰 원문은 DB에 저장하지 않는다.
  고객·PM 세션 토큰과 일회용 nonce는 SHA-256 확인값만 저장한다.
- 고객 서버 세션에는 고정 만료일을 두지 않는다. 로그아웃과 비밀번호 변경 시 종료한다.
  브라우저의 쿠키 저장 한도는 별개다(현재 Max-Age 400일). 쿠키를 잃은 기기는 재접속해야 한다.
- 현재 내부 세션은 Google가 발급한 ID token의 `exp`까지 확인한다. 별도 임의 기간을 더하지 않는다.
  실제 UI의 Google 증명 갱신·재인증 연결은 아직 미구현이다. 이는 배포 전 필수 작업이며,
  ‘Google가 로그인을 요구할 때만 종료’라는 기존 사용성을 최종 검수해야 한다.
- 10분 만료 nonce는 로그인 도중만 쓰며 DB에서 한 번만 소비한다. 로그인 유지기간과 다르다.
- IP별 인증 경로당 분당 20회 이후는 429·Retry-After 60초다. IP 원문은 저장하지 않는다.
  기업 계정을 실패 횟수로 잠그거나 이메일을 보내지 않는다.
- 권한은 Notion에서 매 요청 다시 읽는다. 등록 제거·담당 변경을 캐시 때문에 5분 이상 유지하지 않는다.
  조회 오류 때는 편집을 허용하지 않는다.

Google 토큰은 `jose`로 RS256 서명, Google 발급자, 앱 ID, 만료, 이메일 인증, nonce를 확인한다.
이메일 문자열이나 브라우저가 보내는 역할만 믿지 않는다.
[Google 공식 확인 기준](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token)을 따른다.

## 내부 권한 표

사용자가 지정한 비공개 Notion 「권한 대시보드」 아래의 하위 페이지에 생성했다.
권한 표 DB ID는 `3df815d7-12b9-8174-812e-f72174dacc99`다.
API 키 보관 상위 페이지는 연동에서 접근되지 않았으며, 사용자가 연결한 별도
하위 페이지만 사용했다. 상위 페이지의 API 키·다른 내용은 읽지 않았다.

| 속성 | Notion 종류 | 의미 |
|---|---|---|
| 이름 | title | 사람이 확인할 이름 |
| 이메일 | email | Google가 확인한 이메일과 일치하는 내부 계정 |
| 역할 | select: PM / 대표 | 대표는 파일럿 기업 접근, PM은 담당 관계 확인 |
| 담당 기업 | relation → 기존 공유페이지 DB | PM이 접근할 기업. 기업명 문자열로 권한을 판단하지 않음 |

사용자가 지정한 대표 계정 1개를 등록했다. 계정 이메일은 공개 코드·문서에 복사하지 않는다.
같은 이메일의 중복 등록·알 수 없는 역할·불완전 담당 관계는 거절한다.

## 설정과 이관

서버 secret: `AUTH_PEPPER`, `NOTION_TOKEN`.
비밀이 아닌 설정: `APP_ORIGIN`, `GOOGLE_CLIENT_ID`, `INTERNAL_USERS_DB_ID`.
실제 Google 앱 ID·출처·Notion 권한 표 연결 전에는 내부 로그인이 성공하지 않는다.
설정이 빠졌다고 기존 담당자 공용 비밀번호로 대체하지 않는다.

```powershell
# 기존 비밀번호는 메모리에서 읽고 확인값만 신규 DB에 쓴다.
# .env의 NOTION_TOKEN·AUTH_PEPPER 필요. 기존 확인값이 있으면 검증만 하며 덮어쓰지 않는다.
node worker/scripts/provision-private-customer.mjs
```

이관 SQL 임시 파일은 웹 저장소 밖 OS 임시 폴더에서 삭제한다.
도구 출력에는 기업 slug·생성 여부·검증 여부만 있다.
이관 확인 후에도 새 환경의 고객 데이터·실제 로그인 검수 전까지 Notion 원문은 유지한다.

## 현재 검증·남은 연결

- 인증 스키마는 로컬·원격 고객 전용 D1에 적용됐다.
- 위프코리아 기존 비밀번호 확인값을 원격 DB에 등록하고 동일 비밀번호 검증을 확인했다.
  실제 고객 브라우저 로그인 성공과 구분한다. 원문은 출력·새 DB 저장하지 않았다.
- 공개 route·workers.dev·미리보기는 비활성이다. 별도 고객 서버는 접근 대상 없이 배포했다.
- 신규 서버 `AUTH_PEPPER`·`NOTION_TOKEN` secret을 등록했다. 기존 운영 중계 서버의 secret은 변경하지 않았다.
- 고객 페이지 정상 결과 0건, 고객·내부 세션 0건. 비밀번호 확인값은 1건이며 원문이 아니다.
  고객용 화면·데이터 API는 아직 없다.
- 자동 검사는 합성 계정·실제 서명 라이브러리로 수행하며 실제 Google 사용자 로그인은 미실행이다.
- Notion 권한 표·대표 등록 완료. 실제 `resolveStaff` 조회에서 대표·위프코리아 권한 확인 완료.
  실제 Google 사용자 로그인 성공과 구분한다.
- Google 앱 ID·APP_ORIGIN은 아직 미설정. PC 전환 요청 시 브라우저 URL은 Google Cloud의
  `growthhigh-client` 프로젝트 인증 클라이언트 화면이었다. 실제 앱 생성·설정 저장·로그인 완료는 미확인이다.
- 실제 로그인·세션 갱신 UI와 검수는 남아 있다. 설정 부재를 공용 비밀번호로 우회하지 않는다.
- 전체 24개 파일·317개 검사 통과. 신규 인증 18개는 고객·PM 분리, 비밀번호 변경,
  nonce·위조 서명·담당 변경·요청량 제한·합성 Google 증명의 전체 로그인 연결을 검사했다.
- 이관 도구 재실행은 `created:false`, 기존 비밀번호 검증 성공으로 종료했다. 확인값을 덮어쓰지 않았다.
- 운영 의존성만 검사한 `npm audit --omit=dev`는 취약점 0건. 전체 개발 의존성 무결함을 뜻하지 않는다.
