# 공지를 클라이언트 페이지에서 줄 단위로 고친다

담당자가 미팅·통화 뒤에 공지를 갱신하려면 노션을 찾아 들어가야 했고, 고쳐도
다음 빌드까지 페이지에 뜨지 않았다. 클라이언트 페이지의 공지 화면에서 항목을
그 자리에서 고치고 보탤 수 있게 하고, 저장하면 노션에 쓴 뒤 재빌드를 걸어
1~2분 안에 반영되게 한다.

## 고려한 것

- **페이지 안에 블록 편집기를 만든다.** 공지는 4단 중첩·서식·첨부가 섞인 노션
  블록 트리다. 이걸 온전히 다루려면 노션 편집기의 축소판을 만들고 노션이
  블록 타입을 늘릴 때마다 따라가야 한다. 2~3주 + 영구 유지보수라 접었다.
- **「편집」 버튼이 노션을 새 탭으로 연다.** 서식은 100% 충실하고 며칠이면
  되지만, 요청의 알맹이였던 「한 줄 적기」에 매번 탭 전환이 붙는다.
- **줄 단위 편집(채택).** 화면의 각 줄은 노션 블록 하나와 1:1 이다. 빌드가
  블록 id 를 데이터에 함께 실으면, 고치기는 블록 하나 patch, 보태기는 자식
  append 로 끝난다. 편집기가 필요 없다.
- **노션을 iframe 으로 끼운다.** 불가능하다. 노션이
  `frame-ancestors 'self' https://app.notion.com` 과 `x-frame-options: SAMEORIGIN`
  을 내린다.

## 남는 것

- **중계가 하나 생긴다.** 레포 루트는 통째로 웹에 서빙되므로 브라우저에 노션
  토큰을 둘 수 없다. Cloudflare Workers 가 담당자 확인 → 노션 호출 → 재빌드
  신호를 맡고, 토큰은 거기에만 산다.
- **노션이 계속 원본이다.** 페이지에서 고친 것도 노션에 들어가므로, 다음
  빌드가 편집을 덮어쓰지 않는다.
- **담당자 확인은 공용 비밀번호 하나다.** 누가 고쳤는지는 남지 않는다.
  클라이언트 페이지마다 담당자가 한 명이라 받아들였다.
- **서식은 `**굵게**` 같은 표시로만 쓴다.** 첨부와 커스텀 이모지가 든 항목은
  글로 적을 수 없어 잠긴 항목이 된다 — 그 줄은 노션에서만 고친다.
- **봉투 데이터로는 편집할 수 없다.** 빌드의 블록→HTML 변환은 되돌릴 수 없게
  깎는다(첨부는 이름만, 모르는 블록은 버림). 편집 모드는 노션에서 원본 블록을
  새로 읽어야 한다.
