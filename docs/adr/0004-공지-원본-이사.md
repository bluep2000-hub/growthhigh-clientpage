# 공지의 원본을 노션에서 옮긴다

`0003` 은 편집기를 만들면서 「노션이 계속 원본이다」를 토대로 삼았다. 그 토대를
뒤집는다. 공지의 원본은 이제 중계 서버가 가진 저장소(Cloudflare D1)에 있고,
노션 공지 DB 는 더 쓰지 않는다.

> `0003` 의 토대 한 줄만 뒤집는다 (partially supersedes ADR-0003).
> 편집기의 목적·화면·권한·배포 방식은 `0003` 그대로다.

## 뒤집는 이유

`0003` 은 편집기의 모양을 정한 것이 취향이 아니라 **노션 API 의 벽**이라고 적었다.
그 진단은 맞았다. 그래서 편집기는 벽을 피해 다니는 모양이 됐다 — 하위 항목이 있는
줄은 옮기지 못하고, 종류를 바꾸면 그 줄의 주소가 바뀌고, 표의 열은 못 늘리고,
한 번에 나가는 손질에 무게 상한이 붙었다.

담당자에게 「노션처럼 자유롭게 편집이 안 된다」는 말이 돌아왔다. 맞는 말이고,
원인은 편집기가 아니라 노션 API 다. **벽 안에서는 이 이상 넓힐 수 없다.**

그리고 `0003` 이 세운 전제 하나가 사실이 아니었다. **노션 공지를 읽는 사람이 없다.**
담당자 본인 말고 아무도 열지 않고, 개별 블록에 댓글도 달지 않는다. 노션 공지 DB 는
이름만 원본이었고 실제로는 빌드 재료였다. **아무도 읽지 않는 것을 원본으로
떠받치느라 편집을 좁히고 있었다.**

원본이 우리 것이 되면 벽이 통째로 사라진다. 옮기기는 배열의 원소를 옮기는 일이 되고,
종류 바꾸기는 값 하나를 고치는 일이 된다.

## 고려한 것

- **벽 안에서 최대한 넓힌다** (`#26` 표 · `#27` 첨부·그림·코드). 제일 싸고, 지금
  잠긴 것의 일부를 연다. 그러나 순서·중첩·종류·섹션은 **끝내 안 열린다.**
  「자유롭게」라는 요청에 닿지 못한다.
- **이중 저장.** 노션에 되는 만큼 쓰고 안 되는 것만 우리 저장소에 둔다. 원본이
  둘이 되어 「어느 쪽이 맞나」를 저장할 때마다 풀어야 한다. **지금보다 나쁘다.**
- **원본을 옮긴다 (채택).** 3~4주. 노션이 공짜로 주던 버전 기록과 검색을 잃는다.
  읽는 사람이 없으므로 그 손실을 감수한다.

## 정한 것

- **저장소는 D1 이다.** 쓰고 나서 바로 읽으면 반드시 방금 쓴 것이 나온다.
  KV 는 전파에 최대 60초가 걸려 「저장 → 재빌드」 사이에 옛 공지가 나갈 수 있고,
  레포에 커밋하는 길은 **레포 루트가 통째로 웹에 서빙되므로 공지가 평문으로
  공개된다** — 그래서 탈락이다.
- **공지 한 건이 문서 하나다.** 저장은 문서를 통째로 덮어쓴다. 줄마다 따로 보내지
  않는다. **이것이 자유도의 알맹이다** — 순서와 중첩이 배열을 바꾸는 일이 되어,
  하위 항목이 몇 개든 상관없어진다.
- **반영은 재빌드 그대로다.** 저장하면 재빌드가 걸리고 1~2분 뒤 클라이언트에게
  닿는다. 클라이언트 페이지는 계속 정적 파일이고 봉투도 그대로다. 클라이언트가
  중계 서버에서 직접 읽게 하면 즉시 반영되지만, **중계 서버가 멈추는 순간
  클라이언트 화면에서 공지가 사라진다.** 1~2분은 그 위험을 살 만한 값이 아니다.
- **저장할 때마다 이전 판을 남긴다.** 최근 20판을 보관하고 그 안에서 되돌린다.
  노션이 공짜로 주던 것이라 없으면 담당자가 한 번 실수했을 때 복구 수단이 아예 없다.
- **옮겨 오지 않는다.** 지금 노션에 있는 공지는 그대로 두고 빈 상태로 시작한다.
  담당자가 어차피 새로 쓴다. 이관 코드를 쓰지 않는 대신, **페이지에서 첫 공지를
  만들 수 있어야 한다** — 지금은 공지가 0건이면 편집 모드 자체가 열리지 않는다.

## 사라지는 것

- **잠긴 항목.** 노션이 쓰기를 받아 주지 않던 것이 없어지므로 개념 자체가 없어진다.
- **지우고 다시 만들기.** 옮기기와 종류 바꾸기가 배열 조작이 된다. 주소가 바뀌지
  않고, 하위 항목을 다시 만들지 않고, 반쯤 성공한 상태가 생기지 않는다.
- **한 저장의 무게 상한.** 바깥 호출 천장이 없어진다.
- **줄 단위 어긋남 판정.** 아래 「남는 것」으로 자리를 옮긴다.
- **마크다운 왕복.** `0003` 이 걷어내기로 한 것이 여기서 함께 없어진다.

## 남는 것

- **어긋남은 공지 한 건 단위가 된다.** 담당자 둘이 같은 공지를 동시에 고치면 한쪽이
  통째로 막힌다. 줄 단위로 갈라 살리지 않는다 — 문서를 통째로 쓰기 때문이다.
  담당자가 기업마다 한 명이라 실제로 부딪힐 일이 드물다는 판단이다.
- **노션 공지 DB 는 과거 기록으로만 남는다.** 새로 쓰지도 읽지도 않는다. 지우지도
  않는다 — 지난 공지가 거기 있고, 남겨 두는 데 드는 값이 없다.
- **커스텀 이모지를 넣을 수 없다.** 그것은 이모지가 아니라 노션 워크스페이스에
  올려 둔 그림이다. 노션을 떠나면 넣을 수단이 없다. 일반 이모지는 그냥 글자라
  아무 상관이 없다. 담당자가 쓰지 않는 것을 확인했다.
- **그림·첨부 올리기와 표 편집은 다음 단계다.** 이번에 여는 것은 **글 편집의 자유**
  — 순서·중첩·종류·섹션이다. 그림을 넣으려면 파일 저장소와 올리는 화면이 함께
  붙어 기간이 배로 는다.
- **`0003` 의 나머지는 그대로 선다.** 클라이언트 페이지는 정적 파일이고 봉투로
  잠기며, 노션 토큰은 중계 서버에만 있고, 담당자 확인은 공용 비밀번호 하나이고,
  한 번의 저장이 재빌드 한 번을 부르며, 부분 실패는 정직하게 드러낸다.
- **`#22`·`#23`·`#25`·`#26`·`#27` 은 다시 쓴다.** 전제가 바뀌었다. `#23` 이 만든
  「지우고 다시 만들기」 기계는 이 결정과 함께 버려진다 — 그것은 노션 API 의 벽을
  피해 다니느라 필요했던 것이고, 벽이 사라지면 필요가 없다.
